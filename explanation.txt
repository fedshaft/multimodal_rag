1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
When running `npm start` and `npm run dev` in `/Users/Koushigan/projects/blackhole 2`,
both commands failed immediately with exit code 254 and error `ENOENT`.

The root cause is straightforward:
- The project in this directory is a Python-based Multimodal RAG application
  paired with a Vanilla HTML5/CSS3/JavaScript frontend.
- It is NOT a Node.js / npm package project.
- There is NO `package.json` file in `/Users/Koushigan/projects/blackhole 2`.
- `npm` (Node Package Manager) mandates the existence of a `package.json` manifest
  file in the working directory to discover, parse, and execute lifecycle scripts
  such as `start` or `dev`. Without this file, npm cannot run anything.

2.2. Line-by-Line Error Deconstruction
----------------------------------------
Output Log:
  npm error code ENOENT
  npm error syscall open
  npm error path /Users/Koushigan/projects/blackhole 2/package.json
  npm error errno -2
  npm error enoent Could not read package.json: Error: ENOENT: no such file or directory, open '/Users/Koushigan/projects/blackhole 2/package.json'
  npm error enoent This is related to npm not being able to find a file.

Detailed breakdown of terms and codes:

- Exit code 254:
  A non-zero shell exit status generated by npm to indicate an abnormal, fatal
  termination before any target script or sub-process could even be spawned.

- ENOENT:
  An acronym originating from POSIX C headers meaning "Error NO ENTIty" or
  "Error NO ENTry". In operating systems, it signifies that a named file or
  directory does not exist on the file system at the designated path.

- syscall open:
  Refers to the low-level operating system system call `open()`. Node.js uses
  libuv to invoke `open()` on `package.json` to read configuration and scripts.
  The OS returned a file-not-found signal to this system call.

- path /Users/Koushigan/projects/blackhole 2/package.json:
  The absolute file system path that npm attempted to open and parse.

- errno -2:
  The numerical error identifier defined in the standard C library / OS kernel
  (`-2` on UNIX/macOS/Linux corresponds to `ENOENT`).

- "Could not read package.json":
  The human-readable message from npm explaining that the project manifest file
  is completely missing.

2.3. Why the Errors Occurred
------------------------------
Modern web frameworks built on Node.js (such as React, Next.js, Vite, Vue, or
Angular) rely on `package.json` to map commands like `npm start` or `npm run dev`
to shell commands (e.g. `vite`, `next dev`, `webpack serve`).

Because this repository does not use a JavaScript bundler or Node.js runtime,
no `package.json` exists in the directory root. Attempting to use `npm` here is
analogous to running `python main.py` in a directory where `main.py` does not exist.

3.2. Actual Software Stack of This Project
--------------------------------------------
This project ("Black Hole 2") is a state-of-the-art Multimodal RAG
(Retrieval-Augmented Generation) system for querying technical documents (PDFs,
diagrams, slides, code, text) using both text and image embeddings.

The software components actually used in this codebase include:

A. Backend & Web Serving:
   - Python 3: Core programming language for data ingestion, search, and serving.
   - Virtual Environment (.venv): Isolated Python environment containing dependencies.
   - Starlette (v0.x+): High-performance ASGI framework powering `server.py`.
   - Uvicorn: Lightning-fast ASGI web server hosting Starlette on port 8000.
   - Streamlit: Interactive Python framework for live demos and evaluation (`app.py`).

B. Frontend Web Application (web/):
   - HTML5: Semantic structure in `web/index.html`.
   - CSS3: Custom cosmic dark-mode styling, glassmorphism, responsive grid in `web/style.css`.
   - Vanilla JavaScript (ES6+): Interactive client-side logic in `web/app.js` and `web/data_bridge.js`.
   - HTML5 Canvas: Dynamic cosmic starfield and black hole particle simulations.
   - Zero Bundler / Zero Node.js Requirement: The frontend runs directly in any browser
     without compilation or transpilation.

C. Artificial Intelligence & Information Retrieval:
   - Dense Text Embeddings: `BAAI/bge-small-en-v1.5` (~130 MB, 384-dimensional vectors).
   - Multimodal Image/Text Embeddings: `OpenCLIP ViT-B-32` (laion2b_s34b_b79k, ~600 MB).
   - Cross-Encoder Neural Reranking: `BAAI/bge-reranker-base` or `cross-encoder/ms-marco-MiniLM-L-6-v2`.
   - Sparse Keyword Search: BM25 (`rank-bm25` / BM25Okapi).
   - Vector Database: `ChromaDB` (stored locally in `data/chroma`).
   - Document Processing: `PyMuPDF` (`fitz`) for PDF parsing, text chunking, and raster image extraction.
   - Image & Media Processing: `Pillow` (PIL) and `OpenCV` / `ffmpeg`.
   - Generative Vision Language Model (VLM): `Ollama` running `qwen2.5vl:3b` or `qwen2.5vl:7b`.

5. HOW TO RUN THE PROJECT CORRECTLY (COMMANDS & CODES)
--------------------------------------------------------------------------------

Instead of `npm start` or `npm run dev`, use the following commands depending
on which interface you wish to launch:

5.1. Method 1: Running the Full Starlette/Uvicorn Web App (Recommended)
-----------------------------------------------------------------------
This starts the backend API and serves the space-themed frontend at port 8000:

Using the project's virtual environment:
  $ .venv/bin/python server.py

Or using your system/active python environment:
  $ python3 server.py

Once running, open your browser and navigate to:
  http://localhost:8000  (or http://127.0.0.1:8000)

If you want live auto-reloading during development:
  $ .venv/bin/uvicorn server:app --reload --port 8000

5.2. Method 2: Running the Streamlit Interactive Demo
------------------------------------------------------
This launches the Streamlit GUI for ablation testing and model comparison:

  $ .venv/bin/streamlit run app.py

Once running, open:
  http://localhost:8501

(Note: For answer generation via Ollama, ensure `ollama serve` is running in
another terminal with `ollama pull qwen2.5vl:3b`).

5.3. Method 3: Running the Frontend Standalone via Python HTTP Server
---------------------------------------------------------------------
If you only want to view and inspect the frontend interface (`web/index.html`)
without starting the full RAG backend:

  $ python3 -m http.server 8000 --directory web

Then visit:
  http://localhost:8000

5.4. (Optional) Enabling "npm start" and "npm run dev" via package.json
------------------------------------------------------------------------
If you prefer using npm commands as a shortcut for starting the servers, you can
create a `package.json` file in `/Users/Koushigan/projects/blackhole 2/` with
the following contents:

```json
{
  "name": "blackhole-2-rag",
  "version": "1.0.0",
  "description": "Space-Themed Multimodal RAG Web Application",
  "scripts": {
    "start": ".venv/bin/python server.py",
    "dev": ".venv/bin/python server.py",
    "streamlit": ".venv/bin/streamlit run app.py",
    "web-only": "python3 -m http.server 8000 --directory web"
  }
}
```

Once that `package.json` exists in the project root:
  - `npm start` will run `.venv/bin/python server.py`
  - `npm run dev` will run `.venv/bin/python server.py`
  - `npm run streamlit` will run `.venv/bin/streamlit run app.py`
